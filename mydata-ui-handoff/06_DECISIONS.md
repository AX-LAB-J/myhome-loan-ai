# 06. 충돌·미정 사항과 현지 결정표

아래는 계획서의 부족함을 가짜 확정사항으로 메우지 않기 위한 목록이다. 로컬 Codex가 먼저 기존 코드/설정/DB/기획 근거를 찾아 해결하고, 없을 때만 사용자에게 제품 의미가 달라지는 질문을 모아서 한다. 단순 구현 선택은 제안을 사용하고 결정 이유를 기록한다.

이 파일의 D번호는 **결정 번호**다. `01_UI_SPEC.md`의 S09 버튼 D01~D05와 혼동하지 않도록 기록할 때는 `DEC-D01`처럼 접두어를 붙인다.

## DEC-D01 — ‘계산 근거’ 삭제 범위

- 관찰: 사이드 메뉴 ‘계산 근거’에 삭제 메모가 있다. 홈과 단지 상세에는 ‘계산 근거 보기’ 링크가 남아 있다.
- 확정 가능한 것: 별도 사이드 메뉴 ‘계산 근거’는 최신 주석상 제거 대상.
- 미확정: 본문 링크까지 모두 제거인지, 메뉴만 제거하고 다른 화면에서 근거를 제공할지.
- 현지 조사: 기존 근거 화면/모달, 최근 요구사항/커밋, 기획 코멘트.
- 제안: 메뉴 삭제는 반영하고 본문 링크 정책은 확인해 한 곳으로 통일한다. 링크를 목적지 없이 남기거나 임의 ‘계산 가정’으로 바꿔 확정하지 않는다.
- 차단 범위: H02/P02의 최종 동작·시각 검수만. 다른 화면 구현은 진행 가능.

## DEC-D02 — 합성 데이터와 실제 개인정보

- 관찰: 홈/탐색/상세에 합성 기준 배지, 메뉴에 합성 데이터 기반 서비스, 상세 출처에 합성 DB 실거래 참조값이 있다.
- 사용자 요구: DB에 있는 개인정보가 화면에 표시되어야 한다.
- 미확정: 합성 고객 DB인지 실데이터인지, 금융정보와 부동산 데이터의 성격이 각각 다른지.
- 현지 조사: 데이터 생성/수집 경로, 샘플 문서, 메타데이터, 기존 모드 설정.
- 원칙: UI 배치와 사실 표기를 분리한다. 실제 금융정보를 ‘합성’으로 잘못 표시하지 말고, 금융·거래 출처가 다르면 각각 표시한다. 출처 모드로 결정할 수 없으면 사용자에게 확인.
- 차단 범위: 출처 배지 최종 문구, 개인정보 처리/데모 사용자 선택 판단.

## DEC-D03 — ‘사용자 바꾸기’ 의미

- 관찰: 메뉴에 고객 ID와 사용자 바꾸기 버튼.
- 미확정: 합성 고객 선택, 관리자용 전환, 일반 로그인 전환 중 무엇인지. 선택 화면은 없음.
- 현지 조사: 기존 인증/역할/개발 사용자 선택 기능.
- 제안: 합성 데모면 허용된 테스트 사용자 목록, 실제 서비스면 기존 인증 흐름을 사용한다. 고객 ID 입력만으로 실고객 금융정보를 조회하는 기능을 추가하지 않는다.

## DEC-D04 — 두 금리 스위치의 차이

- 관찰: 홈 ‘금리 +1%p로 다시 계산’, 계산 가정 ‘금리 +1%p로 함께 계산’.
- 관찰: 후자의 설명은 상세 금리 비교와 예상 대출 범위 사용. 상세 표는 동일 원금·만기에 금리만 변경.
- 미확정: 홈은 임시 스트레스 시나리오인지, 저장 설정인지; 두 스위치 동기화 여부; 비교 off 시 상세 레이아웃.
- 현지 조사: 기존 시나리오/옵션 상태와 계산 함수.
- 제안: 현재 금리 자체를 덮어쓰는 처리와 비교 여부를 분리한다. 임시 시나리오·비교 생성 여부를 별도 상태로 다루되 실제 기획 의도 확인 후 확정.

## DEC-D05 — 구매력 구간과 홈 ‘이 범위’

- 관찰: 안정권·가능권·한계권·범위 밖 설명과 계산상 최대가 있으나 숫자/공식은 자리표시자.
- 미확정: 경계 산식·포함 관계·우선순위·큰 홈 금액·탐색 버튼 전달 범위.
- 현지 조사: 기존 계산기·설정·테스트가 최우선.
- 원칙: 법규나 임의 수치를 가져와 채우지 않는다. 큰 금액을 대출 한도로 오해하지 않는다.
- 차단 범위: 계산 정확성 및 홈→탐색 기본 조건. UI 골격/원천 데이터 연결은 진행 가능.

## DEC-D06 — 지역·면적·연도 필터와 지도 필터 시트

- 관찰: 드롭다운 `○○구 / 전용 ○○㎡ / YYYY년 이후`; 지도 카드에 `YYYY년 이후 거래`.
- 추론: 연도는 거래 기간일 가능성이 높다. 준공연도라고 확정할 근거는 없음.
- 미확정: 범위 옵션·기본 선택·단일 면적/면적 구간·정렬 추가 옵션·필터 시트 구성.
- 현지 조사: 기존 검색 API와 실제 데이터 컬럼.
- 제안: 동일 지역·면적·거래 기간 모델을 목록/지도에서 재사용. 없는 옵션을 꾸며내지 않음.

## DEC-D07 — 지출을 월 총지출만 표시

- 관찰: 큰 수정 메모가 있고 기존 카테고리·주거비 제외 스위치·기타 고치기가 남아 있다.
- 구현 방향: 최신 메모에 따라 지출 세부 분류 UI를 제거하고 월 총지출을 중심으로 표시.
- 미확정: 주거비 제외 기능도 없애는지, 계산기에서는 계속 주거비를 제외하는지, 총액을 직접 수정 가능한지.
- 현지 조사: 지출 집계/주거비/기존 상환 중복 처리와 사용자의 현재 요구.
- 원칙: 화면 단순화 때문에 계산 입력 의미를 조용히 바꾸지 않는다. F06/F07은 최신 화면 유지 여부가 결정될 때까지 ‘잔존 컨트롤’로 추적한다.

## DEC-D08 — 채팅 조건의 지속성과 새로 시작

- 관찰: 새로 시작, 적용 조건 X, 되돌리기, 결과 보기. 폼 저장 성공 시 AI 대화 새 시작은 명시.
- 미확정: 채팅 조건은 일시 시나리오인가 저장 가정인가; 새 시작 시 조건까지 복구하는가; undo 범위와 만료.
- 현지 조사: 기존 세션/가정/조건 저장 방식.
- 제안: 저장된 기본 가정과 일시 채팅 조건을 분리. X 닫기는 보존. 새 시작이 초기화하는 대상을 명시. 원천 금융정보는 채팅으로 변경하지 않는다.

## DEC-D09 — ‘가구 인원수에 따른 거래 추가 예정’

- 관찰: 단지 상세 현금흐름 근처에 해당 파란 메모.
- 미확정: 거래 추천 필터, 비교 집계 조건, 가구 생활비 계산, 별도 거래 정보 중 무엇인지 알 수 없음.
- 현지 조사: 가구원 수 데이터·관련 요구/로직 존재 확인.
- 원칙: 예정 메모를 완성된 요구로 취급하지 않는다. 가구원 수에 따라 임의 생활비/대출 규칙을 추가하지 않는다.
- 차단 범위: 이 추가 기능만. 기본 상세 화면 구현을 막지 않는다.

## DEC-D10 — 시장 참고와 비슷한 구매자 집계

- 관찰: 시장 참고는 접힌 상태만, 상세에는 자기자금/대출 비중 중앙값과 최소 표본 억제 문구.
- 미확정: 펼친 내용, 비교 대상 정의, 최소 공개 건수, 데이터 존재.
- 현지 조사: 실제 집계 테이블/쿼리/정책.
- 제안: 기존 집계가 있으면 연결하고, 없으면 데이터 없음/미지원으로 처리. 다른 고객 개인 레코드를 직접 나열하거나 임의 통계를 넣지 않는다.

## DEC-D11 — 연결 해제와 데이터 삭제 범위

- 관찰: 불러온 재무정보가 지워지고 구매력 계산이 불가능하다는 안내.
- 미확정: 외부 연결/동의 철회, 앱 복사본 삭제, 직접 입력 보존, 채팅 보존, 재연결 방법.
- 현지 조사: 동기화/해제 구현, 데이터 소유/보존 정책, 운영/테스트 구분.
- 제안: 앱에서 사용자가 결과를 알고 취소 가능한 확인 단계를 제공. 테스트 계정에서만 검수. 공용 원천 테이블과 다른 고객 데이터는 영향을 받지 않음.
- 차단 범위: 실제 해제 처리. UI·읽기 동작은 먼저 구현 가능.

## DEC-D12 — 다시 불러오기

- 관찰: S07/S09에 갱신 버튼과 마지막 불러온 날짜.
- 미확정: 외부 기관 동기화인지 로컬 DB 새 조회인지; 직접 입력 충돌; 성공 후 계산/채팅 정책.
- 현지 조사: 기존 수집 서비스와 설정.
- 제안: 실제 동작에 맞는 안내, 출처별 값 분리, 새 계산 버전 생성, 오래된 결과 무효화. API가 없는데 성공한 것처럼 시간만 갱신하지 않는다.

## DEC-D13 — 목적 화면이 그려지지 않은 버튼

- 대상: L02 자세히, G03 필터, G07 이 구 단지 보기, G08 목록, D03/D04 동의 상세, Q05 바뀐 결과 보기.
- 현지 조사: 기존 화면/라우트/프로토타입 연결.
- 제안: L02는 홈, 지도 필터는 공통 검색 시트, 구 단지 보기는 선택 구 목록, 동의는 읽기 전용 상세, 결과 보기는 진입 문맥의 갱신 결과. 기존 근거가 있으면 그 흐름 우선.
- 원칙: 이 제안은 Figma에서 목적지가 직접 확인됐다는 뜻이 아니다. 선택 이유를 기록하고 최소 동작으로 구현한다.

## DEC-D14 — 폼 초안·기본값 복원

- 관찰: 기본값으로, 기본값/수정됨 배지, 저장하고 다시 계산.
- 미확정: 즉시 저장 여부, 기본값 복원 후 저장 필요 여부, 미저장 이동/채팅 처리.
- 제안: 폼 초안과 서버 저장값 분리, ‘기본값으로’는 초안 복원, 저장 버튼으로 반영. 미저장 초안은 이동 정책에 따라 보존/안내. 기존 앱 규칙이 있으면 재사용.

## DEC-D15 — 정확한 디자인 속성

- 관찰: 100%에서 약 390px 모바일 폭, 파란 주요 버튼, 연한 배경/흰 카드, 둥근 모서리.
- 미확정: 정확한 HEX, 글꼴/크기/굵기, 간격, 반경, 고정/스크롤 제약조건.
- 현지 조사: Figma 속성/에셋·기존 스타일.
- 원칙: 이 문서에 없는 값을 ‘원본 수치’라 부르지 않는다. 추정으로 구현해야 하면 시각 비교 후 조정하고 추정임을 기록한다. 원본 접근 불가면 이미지 제공을 요청하고 정확한 시각 일치 검수는 미완료로 둔다.
