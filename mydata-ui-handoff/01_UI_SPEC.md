# 01. 화면·버튼 상세 명세

원본: [Figma](https://www.figma.com/design/bj6Q99sd5GYQ0Yi4jlmoOE/?node-id=1-4&p=f) · 2026-10-05 재검토.

각 항목은 별도 표기가 없으면 화면에서 직접 관찰한 구성이다. 표의 ‘동작’은 화살표·안내문에서 확인한 것과 실제 구현을 위한 제안을 구분한다. ID는 추적용이며 화면에 출력하지 않는다.

## 1. 화면 구조와 공통 규칙

| ID | 화면/상태 | 진입 |
|---|---|---|
| S01 | 홈 / 내 구매력 | 기본 진입, 메뉴 ‘내 구매력’ |
| S02 | 왼쪽 사이드 메뉴 | 햄버거 버튼 |
| S03 | 지역·단지 찾기 — 목록 | 메뉴, 홈 주요 버튼, 지도에서 목록 전환 |
| S04 | 지역·단지 찾기 — 구 단위 히트맵 | 우상단 지도 전환, 축소 지도 |
| S05 | 지역·단지 찾기 — 아파트별 지도 | 지도 확대 |
| S06 | 아파트 상세 | 목록 카드, 지도 ‘단지 상세 보기’ |
| S07 | 내 재무 정보 | 메뉴 |
| S08 | 계산 가정 | 메뉴 |
| S09 | 마이데이터 연결 관리 | 메뉴 |
| S10 | LLM 채팅 바텀시트 | 공통 하단 ‘조건을 말로 바꿔 보세요’ |

### 시각 구성

- 연한 회청색 배경 위 흰색 둥근 카드, 짙은 제목, 회색 보조 설명, 파란 주요 버튼이 기본이다.
- 안정권: 진한 파랑 / 가능권: 연한 파랑 / 한계권: 주황 / 범위 밖: 회색. 단어·배지와 색을 함께 표시한다.
- 구 히트맵은 별도 청록색 농도 계열이며 ‘예산 안 거래 수’가 많을수록 진하다. 구매력 4구간 색과 혼동하지 않는다.
- 금액은 오른쪽 정렬을 중심으로 배치하며 주요 구매 가능 집값은 큰 타이포그래피로 강조한다.
- 화면 100% 확대에서 프레임 가로는 약 390px로 관찰되지만 정식 디자인 속성을 추출한 값은 아니다. 프레임·폰트·색 HEX·패딩·반경의 확정값은 현지에서 Figma/기존 스타일로 확인한다.
- [제안] 기존 모바일 폭을 기준으로 320~430px에서 가로 넘침 없이 반응형 처리하고, 넓은 화면에서는 모바일 본문을 중앙 배치한다. 정확한 최대 폭은 현지 디자인 확인 후 정한다.
- Figma의 검은 프레임 외곽선, 빨강/파랑 연결 화살표·테두리, 큰 수정 메모, 프레임 이름, Figma 툴바·가입 배너는 서비스 화면 요소가 아니다.
- 공통 하단 채팅 진입부는 S01/S03/S04/S05/S06/S07/S08에 보인다. S09에는 보이지 않는다. 화면별로 무조건 일괄 추가하지 않는다.
- [제안] 하단 입력부를 고정/스티키로 구현할 때 실제 스크롤 콘텐츠가 가려지지 않게 여백과 safe-area를 확보한다. 고정 여부 자체는 원본의 실제 제약조건 확인이 필요하다.

### 공통 버튼

| ID | 요소 | 동작·검수 |
|---|---|---|
| C01 | 햄버거 | S02 열기. S06에는 뒤로가기 대신 존재하지 않음 |
| C02 | 하단 ‘조건을 말로 바꿔 보세요’ | S10 열기. [제안] 현재 화면/선택 단지/조건을 문맥으로 전달 |
| C03 | 하단 파란 종이비행기 | [제안] 입력이 있으면 같은 입력으로 S10 열고 1회 전송, 비어 있으면 입력할 수 있게 열기. 중복 전송 방지 |
| C04 | 숫자 입력 | [제안] 화면 단위 표시, 입력 검증, 소수·음수·상한 처리는 실제 계약에 따름 |

## 2. S01 홈 / 내 구매력

위에서 아래 순서:

1. 햄버거, ‘내 집 마련’, ‘합성 데이터 기준 YYYY.MM’ 배지.
2. 구매력 카드: ‘지금 소비를 유지하며 감당할 수 있는 집값’, 큰 `○.○억 까지`, ‘계산상 최대 가격은 ○.○억이에요’.
3. 4색 구간 막대와 경계 금액. 아래 2×2 범례:
   - 안정권: `○.○억 이하` / ‘지금 소비 유지 가능’
   - 가능권: `○.○~○.○억` / ‘목표보다 적게 남음’
   - 한계권: `○.○~○.○억` / ‘지금 지출이면 적자’
   - 범위 밖: `○.○억 초과` / ‘계산상 최대 초과’
4. ‘매달 남는 돈’ 카드: 우측 ‘안정권 상단 ○.○억 기준’, 월 소득, 월 지출(차감), 예상 월 상환(차감), 구분선, 큰 남는 돈. ‘목표 여유자금 월 ○○만원과 비교해서 구간을 나눠요.’
5. ‘계산 가정’ 요약: 금리, 만기, 목표 여유자금, 예비비의 칩. 오른쪽 ‘계산 근거 보기’ 링크가 원본에 남아 있음 → D01 결정 필요.
6. ‘금리 +1%p로 다시 계산’ 스위치.
7. 파란 전체 폭 ‘이 범위에서 지역 찾기’.
8. 공통 채팅 진입부 및 ‘실제 매물이나 금융기관의 실제 대출 심사 결과와 다를 수 있어요’ 취지의 작은 안내. 정확한 최종 문구는 원본 대조.

| ID | 요소 | 동작·데이터 |
|---|---|---|
| H01 | 햄버거 | S02 열기 |
| H02 | 계산 근거 보기 | 원본 존재, 삭제 주석 범위 미확정(D01). 빈 링크 금지 |
| H03 | 금리 +1%p로 다시 계산 | [관찰] 재계산 스위치. [현지 확인] 임시 시나리오인지 저장 가정인지 D04로 결정 |
| H04 | 이 범위에서 지역 찾기 | S03 탐색. [제안] 현재 계산 버전/범위를 전달; ‘이 범위’가 안정권인지 계산상 최대인지 D05 확인 |
| H05 | 하단 채팅 입력/전송 | C02/C03 |

**데이터 연결:** 기준일·합성 여부, 현재 사용자 계산 스냅샷, 안정권/가능권/한계권 상한, 계산상 최대, 월 현금흐름, 가정 값. 큰 주금액을 최대 대출액으로 잘못 연결하지 않는다.

## 3. S02 왼쪽 사이드 메뉴

- 배경 화면을 회색으로 덮고 왼쪽 흰 패널. 상단 아이콘, ‘내 집 마련’, ‘감당할 수 있는 집부터 찾기’, X.
- 사용자 카드: ‘고객 ID ○○○’, ‘사용자 바꾸기’, 주택 보유 상태(예: 무주택), 마이데이터 연결 상태.
- ‘찾기’: ‘내 구매력’, ‘지역·단지 찾기’.
- ‘내 정보’: ‘내 재무 정보’, ‘계산 가정’.
- ‘근거와 설정’: ‘마이데이터 연결 관리’. ‘계산 근거’ 메뉴 위치에는 삭제 메모.
- 하단: 녹색 점 + ‘합성 데이터 기반 서비스’, ‘실제 매물이나 대출 승인을 보장하지 않아요’, 데이터 기준일.
- 큰 파란 ‘항목명 수정’은 ‘계산 가정’ 메뉴명에 대한 주석이다.

| ID | 요소 | 동작 |
|---|---|---|
| N01 | X | 메뉴 닫기 |
| N02 | 사용자 바꾸기 | [현지 확인] 기존 합성 고객 선택 기능/인증 설계 확인(D03). 일반 사용자가 임의 고객 ID로 접근하지 않게 함 |
| N03 | 내 구매력 | S01 이동 및 메뉴 닫기 |
| N04 | 지역·단지 찾기 | S03 이동 및 메뉴 닫기 |
| N05 | 내 재무 정보 | S07 이동 및 메뉴 닫기 |
| N06 | 계산 가정 | S08 이동 및 메뉴 닫기 |
| N07 | 마이데이터 연결 관리 | S09 이동 및 메뉴 닫기 |
| N08 | 바깥 배경 / Escape | [제안] 메뉴 닫기, 포커스 복원 |

현재 메뉴 활성 표시를 적용하고 메뉴 오버레이가 열린 동안 배경 스크롤을 막는다. 사용자 교체 시 개인정보·계산·채팅·지도 개인화 캐시를 함께 정리한다.

## 4. S03 지역·단지 찾기 — 목록

위에서 아래 순서:

1. 햄버거, ‘지역·단지 찾기’, 우측 ‘목록 / 지도’ 전환. 목록 활성.
2. 합성 데이터 기준 배지.
3. ‘내 구매력 구간’ 카드, 우측 ‘자세히’, 구간 막대와 안정권/가능권/한계권 상한.
4. 드롭다운 3개: `○○구`, `전용 ○○㎡`, `YYYY년 이후`. 마지막은 지도 카드의 ‘YYYY년 이후 거래’와 관련된 거래 기간 필터로 보이며 준공연도로 단정하지 않는다(D06).
5. 구간 필터: 전체 / 안정권 / 가능권 / 한계권. 원본에는 별도 ‘범위 밖’ 칩이 없지만 전체 목록에 범위 밖 카드는 존재.
6. ‘단지 ○○곳’, ‘가격 낮은 순’ 정렬 드롭다운.
7. 단지 카드 반복: 이름, 구간 배지, ‘이 집’ 위치 표시가 있는 4색 막대, 최근 실거래 `○.○억`, 전용면적, 거래 건수, ‘이 집을 사면 매달 남는 돈’과 금액.
8. 한계권 잔여금은 음수와 주황색. 범위 밖 카드에는 ‘계산상 최대 가격을 넘어요’.
9. 접힘형 ‘시장 참고: ○○구 구매자 대출 현황’, 아래 ‘구매자 집계값만 보여요. 개별 고객 정보는 표시하지 않아요.’
10. 공통 채팅 진입부.

| ID | 요소 | 동작 |
|---|---|---|
| L01 | 목록 / 지도 | S03↔S04/S05. [제안] 동일 필터·선택·계산 버전 유지 |
| L02 | 자세히 | 목적 화면은 미명시. [제안] S01 내 구매력으로 연결(D13) |
| L03 | 지역 드롭다운 | 실제 지역 옵션으로 필터 및 건수 재조회 |
| L04 | 전용면적 드롭다운 | 실제 면적/구간 옵션 확인. 단지와 면적 조합의 가격/건수 갱신 |
| L05 | YYYY년 이후 | 실제 거래 기간 필터 의미 확인 후 적용 |
| L06 | 전체/안정권/가능권/한계권 | 목록 및 건수 갱신. 전체는 범위 밖을 포함하는 원본 상태 재현 |
| L07 | 가격 낮은 순 | 원본에 현재 옵션만 보임. 추가 정렬 옵션은 기존 API/기획 근거 없으면 임의 확장하지 않음 |
| L08 | 단지 카드 | 선택 단지·면적·기간을 보존하여 S06 이동 |
| L09 | 시장 참고 펼침/접힘 | 집계 데이터 조회. 펼친 본문은 원본에 없음(D10) |
| L10 | 하단 채팅 | C02/C03 |

리스트 항목의 ‘거래 ○건’과 헤더 ‘단지 ○곳’을 같은 집계로 연결하지 않는다. 데이터가 많으면 기존 페이지네이션/더 보기 구조를 활용하되 임의 4개 카드 고정은 금지.

## 5. S04 구 단위 히트맵

- 헤더: 햄버거, ‘지역·단지 찾기’, 목록/지도, 지도 활성.
- 범위 칩: ‘안정권만’, ‘안정+가능’(예시 활성), ‘한계권까지’. 우측 조절 슬라이더 모양 필터 아이콘.
- 범례: ‘예산 안 거래 수’, 적음→많음 청록 단계, 사선 패턴 ‘표본 부족’.
- 지도 위 ‘구 단위로 보는 중이에요. 확대하면 단지가 보여요.’ 안내, +/− 확대·축소.
- 구별 영역에 구 이름과 거래 건수. 선택된 구는 진한 외곽선. 표본 부족 구는 숫자를 0으로 표시하지 않고 패턴/문구로 구분.
- 하단 선택 구 카드: 구 이름, `YYYY년 이후 거래`, 예산 안 `○○건`과 전체 중 비율, 구간별 분포 막대, 안정권/가능권/한계권 건수, ‘이 구 단지 보기’, ‘목록’.
- 하단 공통 채팅.
- 원본 ‘네이버 지도 영역 (예시)’와 단순 폴리곤은 설계용 표현이다. 실제 지도 SDK와 실제 경계 데이터로 구현한다.

| ID | 요소 | 동작 |
|---|---|---|
| G01 | 목록 | S03으로 전환, 현재 조건 유지 |
| G02 | 범위 칩 3개 | 예산 안 거래 수/비율/색 농도 재집계. 중첩 범위의 포함 관계를 백엔드 계약으로 고정 |
| G03 | 필터 아이콘 | 펼친 화면 없음. [제안] 지역·면적·거래 기간 필터 시트; D06/D13 확인 |
| G04 | 구 폴리곤 | 선택 구 변경, 카드와 테두리 갱신 |
| G05 | + / 핀치 확대 | 일정 줌에서 S05 단지 표시로 전환. 정확한 임계 줌은 현지 결정 |
| G06 | − / 핀치 축소 | 줌 축소. 지도 상태 유지 |
| G07 | 이 구 단지 보기 | 선택 구를 적용한 단지 탐색. [제안] S03 목록, 기존 흐름이 다르면 기록(D13) |
| G08 | 선택 구 카드 ‘목록’ | [제안] 선택 구/조건을 보존해 S03. G07과 의미 중복은 D13에서 정리 |
| G09 | 하단 채팅 | C02/C03 |

네이버지도 API 키만으로 구 경계·단지 좌표·거래 내역이 생기지 않는다. 누락 시 `02_LOCAL_DISCOVERY.md`에 정확한 데이터 공백을 기록한다.

## 6. S05 아파트별 지도

- 헤더 목록/지도, 구매력 4구간 범례.
- 지역·전용면적·거래 기간 드롭다운.
- 지도 확대/축소, 4구간 색상의 단지 마커. 선택 마커는 원형 외곽 강조.
- 하단 선택 단지 카드: 이름, 구간 배지, ‘최근 실거래’ 금액, ‘매달 남는 돈’, 전체 폭 ‘단지 상세 보기’.
- 공통 채팅 진입.

| ID | 요소 | 동작 |
|---|---|---|
| M01 | 목록 / 지도 | 목록 전환 시 조건 유지 |
| M02 | 지역·면적·기간 | L03~L05와 같은 의미/옵션/서버 필터 |
| M03 | 단지 마커 | 선택 카드 갱신. 상세 진입 전에는 지도 유지 |
| M04 | + / − | 지도 줌 변경, 축소 임계점에서 S04 전환 |

[제안] 큰 데이터셋은 현재 지도 범위 기반 조회·요청 취소·클러스터링 등 기존 구조에 맞춰 최적화하되, 개인화 구간과 선택 상태를 잃지 않는다. 요청한 기준일·면적이 다른 가격을 같은 마커에 섞지 않는다.

## 7. S06 아파트 상세

위에서 아래 순서:

1. 뒤로가기, 합성 데이터 기준 배지, 아파트명, 구간 배지, 구 이름, 전용면적.
2. 최근 실거래 큰 금액, ‘내 안정권 상단보다 ○,○○○만원 높아요’ 같은 비교 문장, ‘이 집’ 위치 막대, 4구간 범례.
3. 자금 계획:
   - 필요 자기자금: ‘집값과 부대비용에서 예상 대출을 뺀 금액’
   - 내 가용 자금: ‘예비비를 뺀 금액’
   - 부족 시 ‘○,○○○만원이 부족해요’
   - 예상 대출 범위 `○.○~○.○억`
   - ‘낮은 값은 금리 +1%p, 높은 값은 지금 금리 기준이에요. 실제 금융기관 심사 결과와 다를 수 있어요.’
4. 매달 남는 돈: ‘이 집을 살 때’, 월 소득/월 지출/예상 월 상환/남는 돈. 목표 여유자금과의 차이 및 구간 설명.
5. 금리가 1%p 오르면: 열 ‘지금 / +1%p’, 행 ‘월 상환 / 남는 돈 / 구간’. ‘대출 원금과 만기는 그대로 두고 금리만 바꿔 계산해요.’
6. 비슷한 조건 구매자: `○○건 기준`, ‘자기자금 비중 중앙값’, ‘대출 비중 중앙값’. ‘○건 미만이면 보여주지 않고, 개별 사례는 공개하지 않아요.’
7. 데이터 기준: 가격 ‘합성 DB 실거래 참조값’, 기준일, 최근 거래 건수, ‘계산 근거 보기’ 링크(D01).
8. 합성 데이터 기반 참고 계산이며 실제 매물이나 대출 승인을 보장하지 않는다는 안내.
9. 공통 채팅 진입.

| ID | 요소 | 동작 |
|---|---|---|
| P01 | 뒤로가기 | 원래 목록/지도 및 필터·스크롤·선택 복원. [제안] 직접 URL 진입이면 S03 대체 경로 |
| P02 | 계산 근거 보기 | 원본 존재; D01 해결 후 기능/제거 확정 |
| P03 | 하단 채팅 | C02/C03, 선택 단지 문맥 유지 |

**중요:** 예상 대출 범위는 금리별 대출 가능량 비교이고, 하단 스트레스 표는 같은 원금·만기의 상환액 비교다. 두 계산을 혼동하지 않는다. 미래 ‘가구 인원수에 따른 거래 추가 예정’ 메모는 의미 미확정(D09)으로 기록하며 제품 UI에 그대로 출력하지 않는다.

## 8. S07 내 재무 정보

위에서 아래 순서:

1. 햄버거, ‘내 재무 정보’.
2. ‘마이데이터에서 YYYY.MM.DD에 불러온 정보예요. 잘못 분류된 값은 직접 고칠 수 있어요.’
3. 출처 범례: ‘마이데이터 / 불러온 값’, ‘직접 입력 / 내가 넣은 값’, ‘다시 불러오기’ 링크.
4. 기본 정보: 나이, 주택 보유. 각 값에 마이데이터 출처 표시.
5. 소득: 가구 연소득(세전), 월 평균 소득. 각 마이데이터 출처 표시.
6. 지출: 월 평균 지출. **수정 메모 ‘지출은 월 총지출만’이 있음.** 아래 기존 상세 항목은 수정 전 잔존 UI로 취급하고 D07에 따른다: 주거비(월세 등), ‘집을 사면 계산에서 빼기’ 스위치와 설명, 생활비, 교통·통신, 기타 ‘분류 확인 필요’, ‘고치기’.
7. 자산: 금융 자산 합계(예금·적금·투자 합계), **‘자산 란에 계좌별 잔액 추가’ 수정 메모**, 기타 동원 자금(직접 입력, 만원), ‘가족 지원처럼 마이데이터에 없는 돈’.
8. 대출: 기존 대출 잔액, 기존 대출 월 상환, 각각 출처 표시.
9. ‘저장하고 다시 계산’. ‘저장하면 구매력을 다시 계산하고 AI 대화가 새로 시작돼요.’
10. 공통 채팅 진입.

| ID | 요소 | 동작 |
|---|---|---|
| F01 | 햄버거 | S02 |
| F02 | 다시 불러오기 | 연결된 출처 갱신. [현지 확인] 실제 외부 동기화인지 DB 재조회인지 D12 |
| F03 | 기타 동원 자금 입력 | 원천 금융자산과 별도 사용자 입력값으로 저장, 숫자/단위 검증 |
| F04 | 저장하고 다시 계산 | 검증→저장→재계산→관련 화면 갱신→AI 대화 새 시작. 실패 중간 상태 처리 필수 |
| F05 | 하단 채팅 | C02/C03. 미저장 폼을 어떻게 취급할지 제안 정책을 정하고 일관 적용 |

**최신 주석에 따른 구현 방향:** 지출은 총액 중심으로 단순화. 계좌별 잔액은 자산 카드 안에서 표시한다. 계좌 행의 정확한 레이아웃은 기획에 없어 [제안] 기관/계좌 별칭 또는 마스킹 식별자/잔액으로 기존 스타일을 확장한다. 상세 계좌번호나 거래 내역 화면을 임의로 추가하지 않는다.

## 9. S08 계산 가정

- 헤더 햄버거, ‘계산 가정’, ‘기본값으로’.
- 설명: ‘대출 규제 기준이 아니라 계산에 쓰는 가정이에요. 바꾸면 구간이 다시 계산돼요.’
- 내 기준:
  - 목표 여유자금(월), 만원. ‘수정됨’ 상태 배지. ‘매달 이만큼은 남기고 싶은 금액이에요. 안정권 기준이 돼요.’
  - 예비비, 만원. ‘기본값’ 배지. ‘집을 산 뒤에도 남겨 둘 현금이에요. 가용 자금에서 빼고 계산해요.’
- 대출 조건:
  - 주담대 금리(%), 만기(년), 기본값 배지.
  - 상환 방식: ‘원리금균등’. 화면에는 선택 드롭다운이 없어 읽기 전용 표시로 관찰됨.
  - ‘한도대출도 포함’ 스위치.
  - 한도대출 금리(%): 미포함 시 비활성. ‘한도대출을 포함할 때만 쓰여요.’
- 계산 기준: 주담대 비율 상한(%), 상환 부담 비율 상한(%), 부대비용 적립률(%). ‘취득세, 중개보수 같은 비용을 집값 대비 비율로 잡아요.’
- ‘금리 +1%p로 함께 계산’ 스위치. ‘단지 상세의 금리 비교와 예상 대출 범위에 쓰여요.’
- ‘저장하고 다시 계산’. ‘저장하면 구간을 다시 계산하고 AI 대화가 새로 시작돼요.’
- 공통 채팅 진입.

|---|---|---|
| A01 | 기본값으로 | 기본 가정 복구. [제안] 폼만 복구하고 저장 버튼으로 반영; 즉시 저장 여부 D14에서 기록 |
| A02 | 목표 여유자금 | 월 금액 수정 |

| A04 | 주담대 금리·만기 | 단위 검증, 기본값/수정됨 표시 |

## 10. S09 마이데이터 연결 관리

- 헤더 햄버거, ‘마이데이터 연결 관리’.
- 연결 카드: ‘연결됨’, ‘○개 기관에서 정보를 가져오고 있어요’, 마지막으로 불러온 날짜, ‘지금 다시 불러오기’.
- 동의 내역: ‘개인(신용)정보 수집·이용 동의’와 동의일, ‘서비스 이용 안내 확인’과 확인일. 각 우측 chevron.
- 연결 기관: 은행(예금, 대출), 카드(결제 내역), 증권(투자 자산) 형태의 리스트.
- ‘연결 해제’ 버튼과 ‘해제하면 불러온 재무 정보가 지워지고 구매력을 계산할 수 없어요.’
- 공통 채팅 진입부 없음.

| ID | 요소 | 동작 |
|---|---|---|
| D01 | 햄버거 | S02 |
| D02 | 지금 다시 불러오기 | F02와 동일한 서버 작업·갱신 상태 사용 |
| D03 | 개인(신용)정보 수집·이용 동의 | 해당 동의 버전/일시/내용 조회. 목적 화면 미제공, 기존 상세 화면 재사용 또는 읽기 전용 시트 [제안] |
| D04 | 서비스 이용 안내 확인 | 해당 안내 내용과 확인 기록 조회. 문구를 임의 법률 문서로 작성하지 않음 |

개발 검수는 테스트 계정/테스트 DB에서 한다. 원천 DB 전체 삭제나 실제 사용자의 연결 해제를 검수 수단으로 실행하지 않는다. 미연결·실패·재연결 화면은 원본에 없으므로 기존 흐름을 확인하고 필요한 최소 상태를 구현한다.

## 11. S10 LLM 채팅 바텀시트

- 어두운 배경 오버레이 위 흰 바텀시트, 상단 핸들.
- 제목 ‘조건을 말로 바꿔 보세요’, 우측 ‘새로 시작’, X.
- ‘적용 중인 조건’과 삭제 X가 있는 조건 칩. 예: ‘월 상환 150만원 이하’.
- 사용자 말풍선(파랑), AI 말풍선(연한 회색).
- 예시 대화 1: 사용자가 ‘월 상환 150만원 이하인 집만 보여줘’ → AI가 적용 결과와 안정권 상단 변화 설명 → ‘되돌리기’, ‘바뀐 결과 보기’.
- 예시 대화 2: ‘강남 출퇴근 50분 이내로 찾아 줘’ → 출퇴근 시간 데이터가 없어 적용하지 못했다는 응답과 지역을 직접 고르는 대안.
- 하단 제안 칩: ‘금리가 1%p 올라도 괜찮은 곳만’, ‘예비비는 남겨 두고 싶어’, ‘목표 여유자금 바꾸기’.
- 입력 placeholder ‘예: 월 상환을 더 낮추고 싶어’, 종이비행기 전송.
- 하단 설명: ‘금액은 AI가 아니라 계산기가 계산해요. AI는 조건을 바꾸고 결과를 설명해요.’

| ID | 요소 | 동작 |
|---|---|---|
| Q01 | X / 바깥 배경 | [제안] 닫기, 대화와 적용 조건 유지. 닫기만으로 초기화 금지 |
| Q02 | 새로 시작 | [관찰] 새 시작 기능. 조건까지 초기화하는지 D08 결정 |
| Q03 | 조건 칩 X | 선택 조건 제거→서버 검증→재계산→화면/칩 동시 갱신 |
| Q04 | 되돌리기 | 해당 적용의 이전 상태 복원. 나중 변경을 잘못 덮어쓰지 않게 버전 확인 |
| Q05 | 바뀐 결과 보기 | 갱신된 결과 화면으로 이동/시트 닫기. [제안] 진입 화면 또는 탐색 결과로 복귀, 필터 유지 |
| Q06 | 제안 칩 3개 | [제안] 의도를 입력창에 채우거나 대화 시작. 수치가 빠지면 확인 질문; 임의 금액 적용 금지 |
| Q07 | 입력 및 전송 | 텍스트 검증→LLM 구조화→허용 변경 검증→계산/검색 실행→결과 설명 |

[제안] 한국어 IME 조합 중 Enter 오전송 방지, 중복 클릭/재시도 중복 반영 방지, 응답 중 상태 표시, 실패 시 이전 유효 조건 유지. LLM 실패해도 폼과 버튼으로 같은 조건을 바꿀 수 있어야 한다.

## 12. 모든 화면의 비정상 상태

원본에는 주로 정상 상태만 있으므로 아래는 [제안] 구현 요구다. 새 화면을 과하게 만들지 말고 기존 카드/시트 스타일을 사용한다.

| 상태 | 표시·동작 |
|---|---|

| 진짜 0 / 음수 | 0원과 음수 정상 표시; 가짜 빈값과 구분 |
| 저장 실패 | 입력 유지, 오류 표시, 성공/대화 초기화 안내 금지 |
| 계산 실패 | 새 버전 준비 실패 표시, 이전 결과는 기준을 명시하거나 노출 중지 |
| 필터 0건 | 조건을 유지한 빈 결과와 수정 수단 |
| 지도 실패 | 재시도와 목록 접근 가능, 지도만 빈 회색 영역으로 방치 금지 |
| LLM 실패 | 메시지 재시도, 중복 조건 적용 방지 |
| 연결 끊김 | 개인화 계산 비활성 및 연결 관리로 안내 |
| 세션 만료/권한 없음 | 기존 인증 흐름, 타인의 값 노출 금지 |
| 오래된 데이터 | 실제 마지막 갱신일 표시. 호출 시각을 데이터 기준일로 위장하지 않음 |
