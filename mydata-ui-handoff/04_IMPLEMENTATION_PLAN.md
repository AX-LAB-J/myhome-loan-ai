# 04. 구현 순서와 단계별 산출물

기존 프로젝트를 유지하면서 실제 DB/API를 연결하는 순서다. 코드 조사 전에 새 라이브러리·새 DB·새 프로젝트를 선택하지 않는다. 소요 기간은 현재 코드의 완성도를 모르므로 확정하지 않는다.

## 단계 0 — 기존 상태 확인과 작업 기준 고정

**작업**

- `02_LOCAL_DISCOVERY.md`에 따라 저장소·실행·DB·기존 연동·계산기를 확인한다.
- 기존 화면을 실제로 띄우고 기획과 다른 점을 기록한다.
- 합성/실데이터 모드, 권한, 스키마, 데이터 단위, 실제 키 설정 상태 확인.
- Figma에서 최종 프레임 크기·폰트·색·간격·반경을 확인하고 기존 스타일과 매핑.
- `06_DECISIONS.md` 중 구현을 좌우하는 D01~D08, D11을 우선 조사한다.

**산출물**: `discovery.md`, `data-mapping.md`, `decisions.md`, 버튼 `traceability.md` 초안.

**통과 조건**: 실제 출처를 모르는 값을 명시했으며, 실행 방법과 데이터 접근 범위가 확인됨. 모든 미정 사항이 풀릴 때까지 작업 전체를 중지하지 않는다.

## 단계 1 — 공통 UI와 화면 틀

**작업**

- 기존 색감·모바일 컨테이너·카드·버튼·글꼴을 토큰으로 정리한다.
- 앱 헤더, 왼쪽 메뉴, 구간 배지/막대, 금액 포맷, 출처 배지, 폼 필드, 채팅 진입부를 공통화한다.
- S01~S10의 화면 순서·레이아웃과 필요한 라우팅/오버레이를 구현한다.
- 현재 프로젝트의 라우터를 사용한다. 문서의 S번호를 URL로 강제하지 않는다.
- 메뉴 선택, 닫기, 뒤로가기, 바텀시트와 배경 스크롤/포커스 복원을 연결한다.
- 임시 fixture는 개발용으로만 명시하고 실제 API 연결 후 제품 코드의 하드코딩 수치로 남기지 않는다.

**산출물**: 화면 골격, 디자인 토큰 대응표, 기본 모바일 시각 비교.

**통과 조건**: 모든 화면에 접근 가능하고 주요 버튼의 위치·문구·배치가 원본과 대응함. 버튼을 스타일만 구현하고 추적표에 완료 표시하지 않음.

## 단계 2 — 사용자와 재무 데이터 읽기 연동

**작업**

- 인증/개발용 고객 선택과 서버 조회 범위를 확인·보완한다.
- DB→서비스→API→프론트 매핑/단위 변환을 적용한다.
- S02 사용자 상태, S07 기본정보·소득·총지출·자산 합계·계좌별 잔액·기존 대출을 실제 값으로 연결한다.
- 출처/기준일/없는 값/로딩/오류를 구분한다.
- 사용자 교체 시 이전 사용자 데이터가 남지 않게 한다.

**산출물**: 실제 데이터 조회, 필드별 매핑 증거, 사용자 범위 테스트.

**통과 조건**: 비식별 테스트 고객의 DB 값과 화면 값이 단위 변환 후 일치. 계좌 합계 차이는 누락/중복/평가 기준으로 설명 가능.

## 단계 3 — 계산 계약과 폼 저장

**작업**

- 기존 계산기에 대표 입력/출력 테스트를 붙이고 구간 경계·기존 상환 중복·금리 스트레스 동작을 확인한다.
- S08 실제 기본값과 사용자 가정을 연결한다. ‘원리금균등’ 표시와 한도대출 금리 활성 상태 반영.
- S07 직접 입력값 저장, S08 저장/기본값 복원, 서버 입력 검증을 구현한다.
- 저장 후 재계산·결과 버전 갱신·대화 새 시작 흐름을 구현한다.
- S01 구매력과 현금흐름/가정/금리 스위치를 실제 계산 결과에 연결한다.

**산출물**: 단일 계산 계약, 저장·재계산 흐름, 단위/경계/실패 테스트.

**통과 조건**: 계산의 사실 근거가 문서화되고 홈과 재무/가정 저장이 연결됨. 규칙 미정이면 해당 수치 정확성 검수는 미완료로 남김.

## 단계 4 — 단지 목록과 상세

**작업**

- 실제 거래·단지·면적·지역 데이터를 매핑한다.
- S03 필터·정렬·건수·카드·범위 밖 안내를 연결한다.
- S06 가격·구간·자금 계획·월 현금흐름·금리 비교·데이터 기준을 구현한다.
- 목록에서 상세로 전달되는 단지/면적/기간/버전을 고정하고 뒤로가기에서 복원한다.
- 시장/비슷한 구매자 집계는 실제 존재하는 안전한 집계에 한해 연결한다. 없으면 명확한 미지원 상태로 남긴다.

**산출물**: 검색↔상세 흐름, 동일값 비교 테스트.

**통과 조건**: 동일 조건의 목록·상세 수치 일치, 0건·누락·범위 밖 처리 정상.

## 단계 5 — 네이버 지도 연동

**작업**

- 기존 로더·키·허용 도메인·실제 호출 성공 여부를 확인한다.
- 실제 구 경계와 필터된 거래 집계로 S04 히트맵 구현.
- 실제 단지 좌표와 동일 계산 결과로 S05 마커/선택 카드 구현.
- 범위 칩, 지도 필터, 확대/축소 전환, 구/단지 선택과 상세 진입을 연결한다.
- 목록↔지도 조건 유지, 늦은 응답 방지, SDK 실패 시 목록 접근을 구현한다.

**산출물**: 실제 지도·히트맵·마커, 조건 일관성 테스트.

**통과 조건**: 예시 그림으로 지도처럼 보이게 한 상태가 아니라 실제 지도 조작 가능. 경계/좌표 데이터가 없으면 누락 이유와 필요한 입력을 별도로 표시.

## 단계 6 — 연결 관리

**작업**

- S09 연결 상태/기관/동의 내역을 실제 데이터에 연결한다.
- ‘다시 불러오기’를 S07/S09에서 공통으로 사용한다.
- 연결 해제의 실제 범위를 확정하고, 사용자 확인·실패·재시도·계산 무효화 흐름을 구현한다.
- 테스트 계정에서 미연결/동기화 실패/부분 실패를 검증한다.

**산출물**: 연결 관리 흐름과 테스트, 실제 해제 범위 문서.

**통과 조건**: ‘연결됨’과 ‘갱신 완료’를 상수로 표시하지 않으며, 원천 DB 전체를 삭제하지 않고 의도된 사용자 범위만 처리.

## 단계 7 — LLM 조건 변경

**작업**

- 기존 OpenAI 호출 경로를 재사용하고 지원 조건 스키마·서버 검증을 구현한다.
- S10 대화·조건 칩·제안 문구·전송·결과 보기·되돌리기·새 시작을 연결한다.
- 기존 계산기/검색 서비스를 도구로 호출하고 전후 결과로 설명한다.
- 데이터 없는 출퇴근 조건 등은 미지원 안내. 수치가 없는 요청은 필요한 질문.
- 네트워크 실패·중복 전송·사용자 교체·저장 후 새 세션·과거 되돌리기 충돌을 처리한다.

**산출물**: 실제 LLM 대화, 결정적 도구 테스트, 제한된 실호출 검증.

**통과 조건**: 응답만 그럴듯하고 실제 필터/금액이 바뀌지 않는 상태는 실패. 적용 성공 설명은 성공한 서버 결과에서만 생성.

## 단계 8 — 통합·모바일·시각 검수

**작업**

- `05_ACCEPTANCE.md` 전체 수행.
- 기준 모바일 폭에서 Figma와 나란히 비교하고 큰 간격·색·글꼴·버튼 위치 차이를 수정.
- 좁은 화면, 실제 키보드, 긴 단지명/큰 금액/많은 계좌/긴 대화를 확인.
- 모든 버튼 추적표를 채우고 미지원·삭제·미정 상태를 명확히 분리.
- 프로젝트 표준 타입 검사·빌드·관련 테스트를 실행.
- 동작 영상/스크린샷을 남길 때 테스트 고객과 비식별 데이터 사용.

**산출물**: `validation.md`, 화면별 시각 비교, 완성된 traceability, 실행 안내, 미해결 목록.

**통과 조건**: 문서의 ‘완료의 의미’를 충족. 검수하지 않은 항목은 ‘통과’로 쓰지 않는다.

## 추천 내부 구성 — 기존 구조에 맞게 조정

| 역할 | 분리 기준 |
|---|---|
| 모바일 공통 레이아웃 | 헤더·메뉴·하단 채팅·safe-area |
| 구매력 표시 | 구간 막대·배지·통화 포맷 |
| 재무/가정 편집 | 폼 초안·검증·저장 |
| 검색 상태 | 지역·면적·기간·구간·정렬·지도 선택 |
| 서버 계산 서비스 | 금액·분류·시나리오 단일 책임 |
| DB 어댑터/집계 | 원천 스키마와 화면 의미 사이 변환 |
| 채팅 조건 서비스 | 해석·검증·적용·되돌리기·버전 |
| 연결 관리 서비스 | 동의·동기화·해제 상태 |

새 라이브러리가 없어도 기존 코드로 구현할 수 있으면 그 경로를 우선한다. 규모를 모르는 상태에서 마이크로서비스나 전면 상태관리 교체를 하지 않는다.
