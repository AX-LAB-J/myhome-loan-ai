# 내 집 마련 모바일 웹 — 구현 인수인계

작성일: 2026-10-05 · 문서 버전: 1.0 · 대상: 기존 프로젝트와 DB에 접근 가능한 로컬 PC의 Codex

## 목적

기존 React·TypeScript 기반으로 추정되는 프론트엔드, FastAPI 백엔드, DB, OpenAI 연동, 네이버지도 연동을 유지·확장하여 Figma UI 기획에 맞는 모바일 웹을 구현한다. 이 문서는 새 프로젝트를 만드는 지시가 아니다. 실제 기술 스택·DB 스키마·계산 로직·연동 상태는 현지 코드로 확인한다.

사용자는 UI·LLM·백엔드 개발을 함께 맡고 있으며, 기본 색감과 모바일 크기의 UI 및 백엔드 설계, API 키, DB가 이미 존재한다고 설명했다. 키가 있다는 사실은 서비스 호출 성공이나 필요한 데이터가 모두 있다는 뜻이 아니다.

## 원본과 확인 범위

- [Figma 원본: 마이데이터B 미니프로젝트 UI 기획](https://www.figma.com/design/bj6Q99sd5GYQ0Yi4jlmoOE/?node-id=1-4&p=f)
- 파일 키: `bj6Q99sd5GYQ0Yi4jlmoOE`, 진입 node: `1:4`.
- 원본에 접근하여 전체 배치와 아래 10개 화면/상태를 확인했다. 두 번째 검토에서는 100% 확대 후 각 화면을 위아래로 이동하며 문구·필드·주석을 읽었다.
- 홈, 왼쪽 메뉴, 지역·단지 목록, 구 단위 히트맵, 확대 지도, 아파트 상세, 내 재무 정보, 계산 가정, 마이데이터 연결 관리 및 별도 채팅 오버레이를 문서화했다. 총 10개 명세 ID로 구분했다.
- 디자인 속성 추출이나 프로토타입 실제 실행 검증은 하지 않았다. 버튼 동작 중 화살표·문구로 확인되지 않은 부분은 제안 또는 미확정으로 표시했다.
- DB·소스코드·실제 API·인증·계산 결과는 이 PC에서 확인하지 않았다. 이 묶음에 실개인정보, API 키, DB 덤프는 없다.
- 이 문서는 화면 이미지 원본의 대체물이 아니다. 구현 PC에서도 원본을 열어 색·글꼴·간격·프레임 크기를 대조해야 한다. 원본에 접근할 수 없다면 사용자에게 해당 프레임 PNG/PDF 또는 Figma 연결을 요청하고, 픽셀 일치 검수는 미완료로 남긴다.

## 문서의 확실성 표기

- **[관찰]**: Figma 화면·문구·화살표에서 직접 확인.
- **[요구]**: 사용자가 요청한 기존 프로젝트 활용, 기획 재현, DB 연동.
- **[제안]**: 기획을 실제 웹으로 만들기 위한 구현 방식. 현지 구조에 맞게 변경 가능.
- **[현지 확인]**: 현재 알 수 없는 DB·코드·계산·정책. 확인 없이 확정 금지.

`○○`, `0.0`, 예시 금액·날짜는 Figma 자리표시자다. 운영 화면에 상수로 복사하지 않는다. 문서 속 영문 데이터 필드명·라우트·컴포넌트명도 제안이며 실제 DB 테이블명이나 기존 API라는 뜻이 아니다.

## 완료의 의미

1. 기획상의 버튼이 모두 동작하거나, 실제로 미지원인 이유와 재개 조건이 명시되어 있다. 아무 동작 없는 버튼으로 완료 처리하지 않는다.
2. 사용자별 값은 올바른 DB/API에서 오며, 화면마다 동일한 계산 버전을 사용한다.
3. 재무정보/가정 저장 → 재계산 → 관련 화면 갱신 → AI 대화 새 시작까지 연결된다.
4. LLM이 금액을 임의 산출하거나 지원하지 않는 검색 조건을 적용했다고 답하지 않는다.
5. 지도·목록·상세의 선택 조건과 수치가 일치한다.
6. 실제 모바일 폭과 키보드 환경에서 화면·하단 입력창·오버레이가 정상이다.
7. 테스트 결과, 시각 비교, 미해결 사항을 근거와 함께 인계한다. 문서만 작성하거나 목업만 만들어 끝내지 않는다.

## 우선순위와 충돌 처리

사용자의 추가 지시 → 확인된 기획 수정 주석 → 기획 화면 본문 → 이 문서의 구현 제안 순으로 해석한다. 단, 수정 주석의 적용 범위가 불분명하면 [06_DECISIONS.md](06_DECISIONS.md)에 기록하고 기존 코드/기획 근거를 먼저 찾는다. 사업 의미가 달라지는 결정만 묶어서 질문하고, 무관한 구현은 계속 진행한다.

개인정보·계산·삭제 범위를 임의로 정하지 않는다. UI를 재현하려고 기존 데이터 구조를 무조건 재설계하거나 기본값을 사실처럼 채우지 않는다.
