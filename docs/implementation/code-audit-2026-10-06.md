# 전체 코드·폴더 점검 (2026-10-06)

## 데이터 전제

사용자는 추후 전처리된 DB를 연결할 예정이다. 이번 작업에서 DB 파일, 연결 설정, CSV 적재·재생성 코드와 원천 데이터는 변경하지 않았다. 현재 화면은 합성 CSV에서 만들어진 SQLite 고객·거래와 직접 입력한 계산 가정을 사용한다.

## 네이버 지도 점의 출처

`apartment_trades`의 단지 주소 → `/api/map` → `geocode_cache` 또는 네이버 지오코딩 → `NaverMap.tsx`의 `Marker` 생성. 기본 노원구 API는 최근 30개 단지를 반환하며, 확인 시 30개 모두 좌표가 있고 국내 유효 범위 안에 있었다. 캐시에는 29개 주소 좌표가 있으며 동일 좌표 중복은 0건이었다. 브라우저에서 실제 네이버 지도 타일과 마커 및 선택 팝업 표시를 확인했다. 따라서 지도 점 자체는 의도된 단지 위치 표시이며 제거하지 않았다.

기존에는 지도용 최신 거래와 목록의 면적·기간 필터 후 최신 거래가 같은 단지에서 달라질 수 있었다. 현재 목록 거래에 지도 좌표를 결합해 마커 팝업·하단 카드·상세가 같은 가격·면적·거래일을 사용한다. 마커 배열을 메모이제이션해 선택 직후 팝업이 재생성되며 닫힐 가능성도 줄였다.

## 수정한 오류·비효율

- 상세 금리 +1%p 비교를 프론트엔드 수식 대신 서버의 기존 `financing`으로 계산. 같은 원금·만기 검증 추가.
- 고객 전환/폼 저장/새 채팅 시작 후 늦게 도착한 이전 채팅 응답이 화면에 나타나지 않도록 요청 버전 확인.
- 고객 ID 검색의 늦은 응답이 최신 검색 결과를 덮지 않도록 처리.
- 숫자 입력을 지우고 다시 입력할 때 값이 즉시 복원되던 문제 수정.
- 지도용 단지 30개의 대출 집계를 개별 DB 조회 30회에서 배치 조회 1회로 변경.
- 현재 모바일 화면에서 쓰지 않는 이전 화면 CSS를 빌드에서 제외. CSS 산출물은 약 22.05KB에서 9.77KB로 감소.
- 실행 안내에 남은 이전 PC 경로와 이전 React 진입점 설명 수정.

## 보존한 파일

`frontend/src/App.tsx`, `styles.css`, `app.py`, `housing_app/ui.py`, `assets/mobile.css`, `housing_app/naver_maps.py`의 `map_html`은 현재 기본 모바일 진입점에는 없지만 이전 UI 구현·Streamlit 테스트·미이관 기능의 참고 자료이므로 삭제하지 않았다. `data`, `models`, `side`, `.env`, `frontend/dist`는 실행·학습·테스트에 필요하다. `logs`, `__pycache__`, 테스트 캐시는 무시 대상 또는 진단 자료이고 다시 생성될 수 있어 이번에는 지우지 않았다. `mydata-ui-handoff` 문서는 요구사항 원본으로 보존했다.
