# 2026-09-30 프로젝트 정리

## 변경

- 실행 모듈을 `housing_app/`, 분석·감사·학습 코드를 `scripts/`, CSS를 `assets/`, 안내를 `docs/`로 분리했습니다.
- 루트 `app.py`는 실행 진입점만 유지합니다. 모든 내부 import와 프로젝트 기준 경로를 새 구조에 맞췄습니다.
- Python 3.12.14 가상환경을 `side/`로 새로 만들고 개발 잠금 파일의 패키지를 설치했습니다. 모델 호환성을 위해 기존 검증된 수치 계산 라이브러리 버전을 유지했습니다.
- 실행·개발 의존성 분리, 전이 의존성 버전·해시 고정, 설치 스크립트, 실행 전 읽기 전용 준비 검사, Ruff 검사/포맷을 추가했습니다.
- 사용하지 않는 import·지역 요약 중복 조회·미사용 변수를 정리했습니다.
- 기존 API 키와 CSV·DB·모델은 변경하지 않았습니다. `.env`의 작업 전후 SHA-256 일치 및 원본 CSV 6개의 감사 보고서 해시 일치를 확인했습니다. 해시와 키 값은 이 문서에 기록하지 않습니다.
- 테스트는 실제 API 키를 프로세스 환경에서만 비활성화합니다. 실제 API 호출이나 키 이동·삭제는 하지 않았습니다.
- Dockerfile, Compose, 빌드 컨텍스트 허용 목록을 추가했습니다. 비밀 파일과 데이터·모델은 이미지에 넣지 않고 별도 볼륨으로 연결합니다.
- 로컬 앱을 `side` 환경으로 재시작했습니다. 로그는 `logs/`, 검증 결과는 `reports/`로 구분합니다.

## 유지한 파일

`data/raw/`는 재검증과 학습에 필요하며 일부 CSV는 런타임 kNN 집단 생성에도 사용합니다. `data/housing.sqlite`, `models/`, 검증 보고서는 앱의 기능이 직접 참조하므로 보존했습니다. 재현 가능한 학습 코드를 불필요한 파일로 취급하지 않았습니다.

## 검증

- 새 가상환경에서 pytest **14개 통과**: DB 합계, 후보 조건, 대출 계산, Deep Agent 도구·대화 이력, 지도 mock, Streamlit UI.

- `ruff check`, `ruff format --check`: 통과.
- `python -m scripts.check`: 실행 데이터·모델·보고서 및 API 키 설정 여부 확인 통과. 키 인증을 의미하지 않습니다.
- 실행 중인 앱의 `/_stcore/health`: `ok`.
- `docker compose --env-file .env.example config --quiet`: 설정 검증 통과.
- Docker 이미지 빌드 시도: 로컬 Linux Docker 엔진 파이프에 연결할 수 없어 미완료. Dockerfile의 실제 빌드·컨테이너 실행은 엔진이 준비된 뒤 확인해야 합니다.

실제 OpenAI 응답, 네이버 지도 인증, 실제 휴대폰, 인터넷 공개 배포는 이번 폴더 정리의 검증에 포함하지 않았습니다. 공개 전 준비 항목은 `deployment.md`에 있습니다.
